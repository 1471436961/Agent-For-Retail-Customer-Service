# P3：比较、calculator 与只读方案准备

2026-10-10 完成。按 POLICY-REGISTER 的 ITEM、MONEY、PAY、RET、EXCH、ADDR、CANCEL 及 U5/U6 实现；平台路径、状态与金额算法不变。

- compare_variants 从真实同产品详情比较 available 候选，精确选项筛选，价格或带明确单位的数值排序，同分保留 API 顺序。数量 codec 的正则只解码目录数量，不处理客户语句。
- calculate 提供有限值 sum/difference/price_difference/round，保留输入与结果；差价 float 顺序累计后 round(total,2)。不使用 eval。
- prepare_change 覆盖七类请求，校验本人/状态/完整地址/两种取消理由/同产品可用变体/重复数量/保存付款/礼品卡余额/退款目的地。方案只存在当前 toolkit；ID 为确定性序列，新方案使同目标未尝试方案失效。
- 订单原成交信息与付款方向保留；取消逐笔列原 charge，不计算净退款。换付款核对唯一原付款与整单余额；换规格按正差价校验。退货只能原支付或首次验证读取时已存在的礼品卡。
- 客户要求指定重复 ID 的某件时拒绝无法表达的精确实例选择；普通有序 ID 操作遵循 U5 的后端匹配约定。

实际执行 unittest discover：73/73 通过，其中 P3 新增12项。七类准备均断言后端记录不变、零业务写入；负例覆盖状态/跨账户/字段/数量/同产品/缺货/保留属性/余额/退款目的地，另有单位、同分、负差额、舍入与重放测试。

用户姓名、意图、理由、偏好与确认仍由 LLM 理解；合成模型测试不能证明真实语义能力。本阶段未开放执行工具、未调用真实 provider、未运行远程评测。P2 推送的 t1 失败轨迹只有通用停止提示，缺少底层异常；根因仍待运行证据。固定 t1 范围未变。
