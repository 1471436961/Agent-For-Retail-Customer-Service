## 当前业务政策

下表“执行位置”说明 LLM 与工具的分工。语义判断不能伪装成确定性证明，后端匹配也不能由模型口头宣称替代。

| ID | 规范化要求 | 执行位置 | 来源 |
|---|---|---|---|
| AUTH-01 | 验证前不读 full profile、订单、地址、支付方法或提供相关敏感信息 | LLM 收集；verify_customer 先 search 后 details | S02 |
| AUTH-02 | 身份 selector 仅 email，或完整 first_name+last_name+postal_code；ID 只能作为候选 | LLM 从完整对话组织参数；工具验证 selector | S02、S19 |
| AUTH-03 | claimed ID 必须匹配独立验证结果；ID 本身不证明身份 | verify_customer 对照后端结果 | S02 |
| AUTH-04 | 一次会话只服务一个已验证客户本人，不能凭亲属关系切换账户 | toolkit 会话绑定；LLM 解释限制 | S02 |
| AUTH-05 | 验证失败不泄露存在性/详情；请求认可信息或网站恢复；不新增锁定次数、flag、hold | 工具返回不敏感结果；LLM 给合规恢复方向 | S03 |
| AUTH-06 | 每个订单访问/操作检查本人归属；错误订单号需查证/澄清，不能读他人明细 | 自有 order_ids 与实际归属校验 | S02、S18 |
| FACT-01 | 回复仅基于客户原话与可访问记录；不猜物流原因、缺失规格或偏好 | LLM grounding；工具提供原始事实 | S07 |
| FACT-02 | customer/product/order 当前字段封闭；不能造 notes、隐藏字段或把 address2 当备注 | 精确 API 适配/领域数据；LLM 边界说明 | S05、S19 |
| FACT-03 | 工程遥测不变成 Agent 跨会话客户记忆 | 会话隔离与日志设计 | S05 |
| CONF-01 | 每次记录变更先完整相关 recap，再获得指向该方案的明确确认；只读无需形式确认 | LLM 语义判断；编排器记录实际展示、版本和用户轮次 | S04、S17 |
| CONF-02 | 改商品、地址、金额、付款/退款去向、范围或操作种类后重新回顾确认 | LLM 识别改口；旧 proposal 失效 | S04、S21 |
| CONF-03 | 暂停、撤回、附条件未满足时不提交；不能挪用无关 yes | LLM 判断当前意图；执行 guard | S04、S21 |
| CONF-04 | 一次性商品修改/换货/退货先收齐同单完整清单；商品修改最后询问补充并等待回答 | LLM 收集；编排时序；工具一次提交 | S04、S11、S17、S21 |
| STATE-01 | 使用七种正常状态；客户措辞不覆盖记录；未知状态停止相关写入 | LLM 查证/解释；工具状态检查 | S08、S18、S19 |
| STATE-02 | pending 才能按政策取消、改订单地址/付款、修改商品 | 执行前重读订单并校验 | S08 |
| STATE-03 | pending (items modified) 不当作普通 pending，再改或取消均不得放行 | 工具资格检查 | S08、S11 |
| STATE-04 | processed 不改/取消/退换；cancelled 不恢复；已有退换请求不重复或追加 | LLM 解释与合法升级；工具检查 | S08、S18 |
| ADDR-01 | 完整新地址回读；纠正后重新完整回读及确认；PUT 包含必需字段 | LLM 收集与纠正；prepare/execute 地址工具 | S10、S17、S19、S21 |
| ADDR-02 | 默认地址与订单地址分开授权、分开执行，不自动连带 | LLM 确定范围；独立 proposal | S10 |

| ARCH-01 | 用户原话的姓名、邮件、理由、同意和偏好由 LLM 理解；不写固定句式正则/词表业务路由 | 用户明确要求及项目设计 | 用户明确要求 |

| ARCH-04 | 一个写入独立批次、转接独立批次；回执回来后决定下一步。多操作不假装原子事务 | 工程设计 | [系统职责](../PROJECT.md) |
