# t1 契约审计修复

依据：[审计报告](T1-CONTRACT-AUDIT-2026-10-12.md)。保持main / retail_plus / python / t1及原绑定范围。

## 当前实现

1. **显式声明ID。** 实时verify_customer schema要求claimed_customer_id；客户未给ID时模型必须显式选null。
   不再默默省略该参数。独立search、ID比较、详情GET的顺序保持不变。
   工具集保留默认参数以兼容原有直接调用；历史恢复用原始schema，实时调用使用明确约束的schema。
   lookup_customer仍复用相同身份门禁，保留给历史恢复及直接调用；实时模型目录仅提供
   verify_customer这一统一核验入口，减少重复工具造成的选择和参数遗漏。

2. **标准文字回复。** 远程模型恢复后，实际评测发现先前强制ReplyIntent JSON会拒绝普通模型文字。
   已恢复契约允许的AssistantMessage.content自然语言回复；提示模型只依据真实成功工具结果回答，
   失败或仅核验成功但未读到详情时不能声称查询完成。模型负责语义理解与事实表达。
   原结构化输出仅保留兼容与相应证据校验，不再作为正常对话的必需格式。
   不解析用户句式，不增加provider参数。自然语言事实正确性由真实模型与评测验证，
   不声称代码能通过格式检查证明每句文字真实。

3. **身份与详情状态分开。** 独立核验成功后GET失败时，工具返回已验证但profile_state=unavailable的
   明确回执，保留客户锁定，不含邮箱等未经加载的字段。Agent同步身份，恢复阶段仅提供
   get_customer_summary和transfer_to_human。成功重读后恢复业务能力。
   实际tau2 Environment.to_json_str会把嵌套原始数值/布尔值转成字符串，因此新增工具回执使用状态枚举，
   不依赖字符串False的布尔真假。Agent自身state仍使用正常JSON布尔值。

4. **目录一致。** 实时模型回复按本轮实际actions检查；历史恢复按完整合法目录检查。
   未提供的工具调用会在宿主执行前被拒绝并给予一次有界纠正机会，不能通过完整目录绕过本轮限制。

5. **可见的回执引用。** 成功工具结果的模型投影增加evidence_call_id，保留原tool_call_id。
   模型从正文中引用实际ID，不需要猜测API协议外层的标识。失败回执不成为成功证据。

工具参数要求模型显式表达选择，实际回执提供证据；不能证明模型永远不会误解用户。
没有添加姓名/邮箱问句正则、案例ID路由、预设客户答案或直接provider客户端。
一般事实解释由模型根据实际工具结果形成，不通过字符串规则判断自然语言真假。
