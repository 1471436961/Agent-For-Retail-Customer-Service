## 已复核的关键约束

1. 身份查询独立执行：先 searchCustomers，核对声明 ID，再 getCustomer；
   ID 单独、混合/不完整选择条件、匹配失败不读取详情，不能会话中切换账号。
   验证不能与依赖读取组成同一批次；所有暴露的客户/订单/目录读取都经过工具身份门槛。
2. 读取订单先核对当前本人订单列表，再核对订单实际归属；路径 ID 按不透明字符串编码。
   API 字段、重复记录、流水方向、枚举和响应形状不由模型猜测。
3. 七类变化先 prepare、实际完整回顾、后续用户输入，再按同一方案 ID 执行。
   新方案撤销旧确认；后台事实变化要求重新准备和确认；一个写入独立批次。
   是否明确同意是模型语义判断，离线模拟不证明模型能够正确识别所有表达。
4. pending 与 pending (items modified) 严格区分；退换仅 delivered；
   不自行提供购买、改数量、部分取消、新付款、任意退款或隐藏行 ID。
5. 重复商品保留数量及顺序。同 ID 处理和浮点差价按 U5/U6 的规定，
   没有用去重、隐藏实例定位或 Decimal HALF_UP 替代正式算法。
6. 取消逐笔原 charge 退款；礼品卡覆盖全部应付金额；退货/换货退款目的地不同；
   受理申请不称到账。退款时间仅用于材料明确规定的具体操作和来源。
7. 写入前记录 attempted；failed/unknown/completed/accepted 的重复执行不发第二次写请求。
   只读观察不能把未知写入重新授权成可重试；没有跨操作原子事务承诺。
8. 转接来自可信 conversation_id；三类语义触发由模型判断；
   accepted 使用固定 notice，accepted/unknown 后禁止继续客户 API；状态按会话隔离并可重放。
